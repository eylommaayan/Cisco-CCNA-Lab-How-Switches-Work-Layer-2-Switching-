# Cisco CCNA Lab: How Switches Work (Layer 2 Switching) 🔄

## 📝 אודות המעבדה (Lab Objective)
מעבדה זו בוצעה ב-Cisco Packet Tracer ומטרתה להמחיש את מנגנוני הליבה של מתגי תקשורת בשכבה 2 (Data Link Layer). 
במעבדה זו חקרתי וניתחתי בזמן אמת (Simulation Mode) כיצד מתגים לומדים כתובות MAC, כיצד הם מקבלים החלטות העברה (Forwarding), ומה קורה כאשר יעד התעבורה אינו ידוע למתג (Flooding).

## 🏗️ טופולוגיית הרשת (Topology)
הרשת מורכבת מתת-רשת יחידה (`192.168.0.0/24`) וכוללת:
* **2 מתגים (Switches):** מחוברים ביניהם דרך ממשק `Fa0/3`.
* **4 מחשבי קצה (PCs):**
  * `PC1` (192.168.0.1) מחובר ל-Switch1 ב-`Fa0/1`.
  * `PC2` (192.168.0.2) מחובר ל-Switch1 ב-`Fa0/2`.
  * `PC3` (192.168.0.3) מחובר ל-Switch2 ב-`Fa0/1`.
  * `PC4` (192.168.0.4) מחובר ל-Switch2 ב-`Fa0/2`.

שאלה 2: דרך אילו ממשקים (interfaces) יעביר כל מתג את הפריים (frame) הראשון?
תשובה:
<img width="1295" height="818" alt="image" src="https://github.com/user-attachments/assets/c31c9204-5f6d-4988-9905-42e0b86d895f" />
Switch1 מעביר דרך הממשקים: Fa0/2 (אל PC2) ו-Fa0/3 (אל Switch2).

Switch2 מעביר דרך הממשקים: Fa0/1 (אל PC3) ו-Fa0/2 (אל PC4).

נימוק הנדסי:

יציאה מ-PC1: המסגרת יוצאת ממשק Fa0 ונכנסת אל פורט Fa0/1 של Switch1.

הצפה ראשונה (Switch1): מאחר שטבלת ה-MAC ריקה (מצב Unknown Unicast / Broadcast), המתג מפעיל מנגנון הצפה (Flooding) ומשכפל את המסגרת לכל הפורטים הפעילים, למעט פורט הכניסה (Fa0/1). המסגרת מגיעה במקביל אל Fa0/2 (PC2) ואל Fa0/3 (Switch2).

הצפה שנייה (Switch2): המסגרת נכנסת דרך Fa0/3. מכיוון שגם Switch2 אינו מכיר את היעד, הוא מציף אותה לכל הפורטים שלו למעט פורט הכניסה (Fa0/3) – כלומר אל Fa0/1 (PC3) ואל Fa0/2 (PC4).

תגובת תחנות הקצה:

PC2 ו-PC3: בודקים את כתובת היעד, מזהים שאינה שייכת להם, ומשליכים את המסגרת לפח (Discard).

PC4: מזהה שהוא היעד המבוקש ומייצר את מסגרת התשובה.

שאלה 3: לאחר הפינג הראשון, דרך איזה ממשק יעבירו המתגים פינג שנשלח מ-PC4 ל-PC1?
תשובה:

Switch2 מעביר את המסגרת אך ורק דרך הממשק: Fa0/3 (לכיוון Switch1).

Switch1 מעביר את המסגרת אך ורק דרך הממשק: Fa0/1 (ישירות אל PC1).

נימוק הנדסי:
לאחר השלמת סבב הפינג הראשון (בקשה ותגובה), שני המתגים כבר אכלסו את כתובות החומרה של PC1 ו-PC4 בטבלאות ה-MAC שלהם:

ב-Switch2: המסגרת מ-PC4 נכנסת דרך Fa0/2. המתג בודק את טבלת ה-MAC שלו, מוצא שכתובת היעד של PC1 רשומה על Fa0/3, ומעביר אותה אך ורק ל-Fa0/3 (ללא הצפה ל-PC3).

ב-Switch1: המסגרת נכנסת דרך Fa0/3. המתג בודק את הטבלה שלו, מוצא שכתובת היעד של PC1 רשומה על Fa0/1, ומעביר אותה בקו ישיר אך ורק ל-Fa0/1 ישירות למחשב היעד (ללא הצפה ל-PC2).

תוצאה: התעבורה מועברת בשידור ישיר (Known Unicast Forwarding), דבר המונע עומס מיותר ושומר על אבטחה ומשאבי רוחב הפס ברשת.

📌 סיכום מסקנות CCNA למעבדה
מתג לעולם אינו לומד כתובות מתוך שדה היעד (Destination MAC), אלא אך ורק משדה המקור (Source MAC).

הצפה (Flooding) מתרחשת במסגרות מסוג Broadcast, Multicast, או מסגרות Unicast שהיעד שלהן אינו קיים כרגע בטבלת ה-MAC (מצב Unknown Unicast).

הצפה לעולם אינה נשלחת בחזרה אל הפורט שממנו נכנסה המסגרת המקורית.

תחנת קצה שאינה יעד המסגרת תסנן ותשליך את המידע ברמת כרטיס הרשת (NIC Discard).
